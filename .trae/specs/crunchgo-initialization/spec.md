# CrunchGo 初始化规范

## 为什么 (Why)
本规范概述了 CrunchGo（基于微信小程序的单店快餐点餐系统）的初始化和设置流程。目标是建立项目结构、数据库模式和核心 API 基础，以支持堂食和自提的点餐流程。

## 变更内容 (What Changes)
- 初始化后端（FastAPI）、前端小程序（Taro + Vue3）和管理后台（Vue3 + Element Plus）的项目代码库结构。
- 设置 PostgreSQL 数据库，包含用户、商品、订单和支付的数据模式。
- 配置 Redis 用于缓存、会话管理和库存锁定。
- 实现认证、菜单管理和订单处理的核心后端 API 接口。
- 开发小程序的基础页面（首页、菜单、购物车）。

## 影响 (Impact)
- **受影响的规范**: 初始设置影响所有后续功能的开发。
- **受影响的代码**: 
    - `/backend`: FastAPI 应用结构。
    - `/frontend-miniapp`: Taro 项目结构。
    - `/frontend-admin`: Vue3 管理后台项目结构。
    - 数据库: 初始迁移脚本。

## 新增需求 (ADDED Requirements)

### 需求: 系统架构
系统应遵循分层架构：
- **前端**: Taro (微信小程序) 和 Vue3 (管理后台 Web)。
- **后端**: Python FastAPI。
- **数据库**: PostgreSQL 用于持久化存储。
- **缓存**: Redis 用于高速访问和锁定。
- **基础设施**: Docker 容器化部署。

### 需求: 用户模块
- **微信登录**: 用户应能使用微信授权登录并获取认证 Token。
- **个人资料管理**: 用户应能查看个人资料和积分余额。

### 需求: 菜单模块
- **分类**: 系统应支持菜单项的分层分类。
- **商品**: 商品应支持多 SKU（例如：规格、辣度）。
- **库存**: 库存应在 Redis 中跟踪以支持高并发，并同步到 PostgreSQL。

### 需求: 订单模块
- **订单创建**: 系统应支持创建订单，并在 Redis 中进行库存检查和锁定。
- **支付集成**: 系统应集成微信支付。
- **订单状态机**: 订单应在状态之间流转：`PENDING` -> `PAID` -> `COMPLETED` / `CANCELLED` / `REFUNDED`。
- **云打印**: 支付成功的订单应触发云打印机的打印任务。

### 需求: 管理模块
- **商品管理**: 管理员应能对商品进行增删改查并管理库存。
- **订单管理**: 管理员应能实时查看和管理订单。
