# CrunchGo 街边点餐系统项目实施方案

## 1. 项目概述
**项目名称**: CrunchGo
**业务场景**: 街边小门店，无堂食区域，主打外带/自提。
**核心需求**: 极速点单、自动排队、扫码即走。
**目标**: 解决高峰期排队拥堵问题，提升出餐效率，降低人工点单成本。

## 2. 技术架构
基于现有技术储备，采用前后端分离架构：

- **前端 (用户端/商家端)**: 
  - 框架: **Taro** (React 语法)
  - 平台: **微信小程序** (依托微信生态，无需下载，扫码即用)
  - UI风格: Crunch Orange (#FF6B00) 主色调，高对比度，适合户外强光环境。

- **后端 (API 服务)**:
  - 框架: **NestJS** (Node.js)
  - 语言: TypeScript
  - 特性: 模块化设计，易于维护和扩展。

- **数据存储与缓存**:
  - 数据库: **PostgreSQL** (存储订单、商品、用户数据)
  - 缓存/队列: **Redis** (处理高并发库存扣减、排队号生成、订单缓存)

## 3. 功能模块设计 (MVP 版本)

### 3.1 顾客端 (小程序)
1.  **扫码点餐**: 扫描门店二维码，直接进入点餐页面（跳过复杂的授权登录，支付时再获取用户信息）。
2.  **极简菜单**: 
    - 瀑布流或列表展示，突出招牌。
    - 简单规格选择（如：冷/热，糖度）。
3.  **快速下单**: 
    - 购物车功能简化，支持“立即购买”。
    - 微信支付集成。
4.  **智能排队**:
    - 支付成功后自动生成“取餐号”（如：A102）。
    - 实时显示“前方排队 N 人”及“预计等待 M 分钟”。
    - 制作完成推送订阅消息（需用户授权）。

### 3.2 商家端 (小程序或 Web 管理后台)
1.  **接单看板**: 
    - 实时新订单语音播报（"您有新的订单"）。
    - 订单列表：待制作 -> 制作中 -> 请取餐 -> 已完成。
2.  **快捷操作**: 
    - 一键“叫号”（触发顾客端通知）。
    - 缺货商品一键下架。
3.  **小票打印**: 
    - 连接蓝牙热敏打印机，自动打印后厨小票和顾客小票。

## 4. 核心业务流程
1.  **顾客**: 进店/排队 -> 扫码 -> 选购 -> 支付 -> 获得取餐号 -> 等待叫号 -> 取餐。
2.  **商家**: 收到订单(打印小票) -> 制作 -> 点击“制作完成”/“叫号” -> 核销(可选) -> 完成。

## 5. 数据模型设计 (简略)
- **Category**: 分类 (ID, 名称, 排序)
- **Product**: 商品 (ID, 名称, 价格, 库存, 图片, 规格配置)
- **Order**: 订单 (ID, 取餐号, 总价, 状态[Pending/Paid/Preparing/Ready/Completed], 支付时间)
- **OrderItem**: 订单项 (关联 Order 和 Product, 记录快照价格和规格)

## 7. 关键难点与解决方案
- **网络波动**: 街边信号可能不稳定。
  - *方案*: 本地缓存菜单数据，断网可看；提交订单时通过 Loading 遮罩确保状态同步。
- **高峰期并发**: 午餐/晚餐时段流量集中。
  - *方案*: 使用 Redis 队列处理订单，前端轮询或 WebSocket 更新排队状态。
